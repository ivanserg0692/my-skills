# Изолированная песочница Filebeat

Это автономная среда для проверки конфигурации и обработки событий Filebeat 9.5.2 перед изменениями основной конфигурации. Она запускается через Docker Compose без Kubernetes и Elasticsearch; Filebeat печатает события и ошибки в консоль. Папка находится в скилле `filebeat-testing`.

## Запуск сценариев

Из каталога `sandbox` запустите исходный сценарий:

```sh
docker compose run --rm conflict test config -e --strict.perms=false
docker compose run --rm conflict
```

В debug-выводе будет ошибка `cannot override existing key with \`host\``. Событие в консоли останется неразобранным. Остановите Filebeat сочетанием `Ctrl+C` после появления результата.

Исправленный сценарий:

```sh
docker compose run --rm fixed test config -e --strict.perms=false
docker compose run --rm fixed
```

В console-событии должны появиться `nginx_time` и `nginx_host`; объект ECS `host.name` при этом сохраняется. Остановите Filebeat после появления события.

Для просмотра только ошибок процессора в выводе найдите строки `Fail to apply processor` и `cannot override existing key`. Для успешного сценария найдите поля `nginx_time` и `nginx_host` в JSON-событии.

## Добавление тестов и процессоры

Замените содержимое `samples/gateway-access.log` своими строками. Filestream использует fingerprint длиной 64 байта, поэтому тестовый файл должен быть не короче 64 байт. Можно добавить несколько строк или файлов с расширением `.log`.

Настройки input, processor, `ignore_failure` и `output.console` находятся в конфигурациях сценариев. Их можно менять или создавать отдельную конфигурацию и сервис Compose для проверки inputs, фильтров, parsing и других процессоров Filebeat. Сохраняйте исходный сценарий конфликта как регрессионный пример; у каждого сервиса должны быть свои `path.data` и временный registry. Не добавляйте зависимости от Elasticsearch или Kubernetes.

Для каждого изменения добавьте строки, соответствующие фактическому формату логов: успешные, граничные и некорректные, если они применимы. Проверьте поля, типы, фильтры потери событий и отсутствие токенов, паролей и других чувствительных значений в результатах. При проверке ошибки процессора отключите скрывающие событие фильтры и сделайте ошибку видимой.

## Изоляция и повторный запуск

Каждый сервис использует отдельный `path.data` и отдельный временный `tmpfs` для registry. Контейнер удаляется после остановки (`--rm`), поэтому следующая команда начинает с пустого состояния и повторно читает образец. Compose отключает строгую проверку владельца конфигурационных файлов, смонтированных с хоста; это нужно для запуска официального образа с локальными файлами и не меняет обработку событий.

Если запускали контейнеры без `--rm`, очистите Compose-ресурсы командой:

```sh
docker compose down --volumes --remove-orphans
```

Для обычного повторного теста дополнительных действий не требуется. Этот стенд проверяет конфигурацию локально; развёртывание изменений в Kubernetes требует отдельного согласования.
